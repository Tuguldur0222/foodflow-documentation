# Confirmed захиалгыг цуцлах шаардлагыг хэрэгжүүлэх

**Төлөв:** нээлттэй [GitHub issue #2](https://github.com/Tuguldur0222/foodflow-documentation/issues/2). **Холбоо:** [SRS FR-13](../../requirements/srs.md), [W06](../../semesters/week-06.md).

Шинэ `Week_03_FoodFlow.docx`-ийн FR-13 нь Pending болон Confirmed төлөвт цуцлахыг шаарддаг. W06-ийн жижиг сургалтын `OrderService` зөвхөн Pending төлөвийг дэмждэг. Энэ ялгааг код, баримт бичиг, тестийн хамт арилгана.

Confirmed төлөвийн шилжилт, цуцлах хугацааны хязгаар, төлбөртэй захиалгын үйлдлийг шаардлага хариуцагчтай баталгаажуулна. Давтан цуцлалтын үр дүнг API contract болон docstring-д ижил тайлбарлаж, бодит хэрэгжилтийн дараа traceability хүснэгтийг шинэчилнэ.

Хүлээн авах шалгуур:

- Өөрийн Pending болон Confirmed захиалгыг тохирсон дүрмийн дагуу цуцална.
- Бусдын захиалга болон Delivered төлөвийг цуцлах боломжгүй.
- Давтан хүсэлтийн зан үйл, exception/HTTP хариу, тест, Sphinx жишээ хоорондоо нийцнэ.
- Төлбөр буцаалтын кодгүй үед буцаалтыг хэрэгжсэн гэж баримтжуулахгүй.

Ахиц, review болон шалгалтын нотолгоог issue-д бүртгэнэ.
