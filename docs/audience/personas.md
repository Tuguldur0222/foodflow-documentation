# FoodFlow-ийн уншигч ба persona

FoodFlow-ийн баримтжуулалтын үндсэн уншигч нь захиалгын үйлдлийг өөрийн программд холбох хөгжүүлэгч юм. Persona нь бичих хэл, жишээ, шалгах асуултыг сонгоход ашиглах зохиомол дүр; бодит хэрэглэгчийн ярилцлага эсвэл зах зээлийн судалгааны орлуулга биш.

| Баталгаажсан зүйл | Доорх олон нийтийн гурван хэлэлцүүлэгт дурдсан асуудал, тэдгээрийн эх сурвалж |
| Баталгаажуулах зүйл | FoodFlow-ийн бодит хөгжүүлэгчтэй ярилцлага, асуудлын эрэмбэ, уншигчийн туршилт |

Эдгээр холбоосыг 2026-10-13-нд шалгасан. Анхны тайлангийн `Stack Overflow 76598428` холбоосын агуулгыг энэ шинэчлэлээр баталгаажуулж чадаагүй тул хоёр дахь асуудлын үндэслэлд шууд уншиж шалгасан FastAPI хэлэлцүүлгийг ашиглав. Олон нийтийн асуудлын жишээнээс FoodFlow хэрэглэгчдийн давтамж, хувь хэмжээг дүгнээгүй.

### Зохиомол persona-ийн хэллэг

> “Амжилттай хүсэлтийн жишээ ойлгомжтой байна. Харин token-оо хаана дамжуулах, алдааны хариуг яаж ялгах, ямар хувилбарт жишээ ажиллахыг нэг дороос мэдмээр байна.”

Энэ өгүүлбэр нь дээрх асуудлуудыг нэгтгэсэн сургалтын зохиомж. 30 минутын ярилцлагаас авсан шууд эшлэл биш. Ярилцлагын бодит хариу ирвэл зөвшөөрөлтэй, нэрийг нууцалсан тэмдэглэлээр солих ёстой.

## Дэмжих persona ба бүтээгдэхүүний эцсийн хэрэглэгч

| Дүр | Үүрэг ба хэрэгцээ | Баримтад өгөх чиглэл | Нотолгооны төлөв |
| --- | --- | --- | --- |
| Билэгт | Backend developer; давхар захиалга, төлөвийн шилжилт, өгөгдөл хадгалах хилийг ойлгох | [SRS](../requirements/srs.md), [архитектур](../architecture/index.md), API гэрээ, тестийг хооронд нь холбоно | Зохиомол persona; бодит ярилцлага хийгдээгүй |
| Номин | Support specialist; захиалгын төлөв, алдааны шалтгаан, хэрэглэгчийн дараагийн алхмыг олох | Алдааны кодын утга, цуцлах боломжтой төлөв, дахин оролдох нөхцөлийг энгийн хэлээр тайлбарлана | Зохиомол persona; support ticket-ийн бодит өгөгдөл байхгүй |
| Саруул | Хоол захиалагч; сонголт, нийт үнэ, захиалгын баталгаажуулалт, түүхээ ойлгох | Хөгжүүлэгчийн хэрэглэсэн гэрээ бүтээгдэхүүний дэлгэцэд зөв үр дүн өгөх ёстой | Зохиомол end-end user |

**End user** гэдэг нь тухайн баримтыг шууд ашиглаж буй хөгжүүлэгчийг зааж болно. Энэ хичээлийн **end-end user** нь хөгжүүлэгчийн бүтээсэн бүтээгдэхүүнийг эцэст нь ашиглах хүн: FoodFlow-д Саруул юм. Ану API-ийн алдааг буруу ойлговол Саруул төлбөр төлөгдсөн эсэх, захиалга цуцлагдсан эсэхийг буруу харж болно. Иймээс баримтын ойлгомжтой байдал нь зөвхөн хөгжүүлэгчийн тав тухаар хэмжигдэхгүй.

## 30 минутын баталгаажуулах ярилцлагын төлөвлөгөө

| Хугацаа | Агуулга | Бүртгэх зүйл |
| --- | --- | --- |
| 0–5 минут | Оролцогчийн үүрэг, хэрэглэдэг хэрэгсэл, API холбосон туршлага | Хувийн мэдээлэлгүй орчны тайлбар; тэмдэглэл авах зөвшөөрөл |
| 5–12 минут | Өмнө тулгарсан auth, response, version-ийн бодит жишээг асуух | Үйл явдал, ажил зогссон шалтгаан, ашигласан баримт |
| 12–22 минут | README ба нэг API жишээг уншуулж, дараагийн алхмыг өөрөөр нь тайлбарлуулах | Тусламж хүссэн хэсэг, таамагласан үг, олсон холбоос |
| 22–27 минут | Алдаатай оролт, өөр хэрэглэгчийн захиалга, цуцлах нөхцөлийг асуух | Үнэн зөв ойлгосон болон буруу ойлгосон ялгаа |

Ярилцлагын үр дүнг нэмэхдээ огноо, арга, оролцогчийн нэргүй ID, ашигласан commit, ажиглалт, дүгнэлтийг бүртгэнэ. Төлөвлөгөө бэлтгэсэн нь ярилцлага хийсэн гэсэн нотолгоо болохгүй.

## Найруулга ба нэршлийн дүрэм

- Үр дүнг эхэнд, үйлдэл ба урьдчилсан нөхцөлийг дараа нь бичнэ. Жишээ нь “Давхар захиалга үүсэхээс сэргийлэхийн тулд …” гэж эхэлнэ.
- Анх хэрэглэсэн техникийн нэршилд Монгол тайлбар өгнө: **idempotency** — нэг хүсэлтийг давтан илгээхэд давхар үйлдэл үүсгэхгүй байх шинж.
- API field, function, exception, header, enum-ийн бичлэгийг өөрчлөхгүй: `order_id`, `Idempotency-Key`, `Pending`. Монгол тайлбар нь эдгээрийн утгыг тайлбарлана.
- HTTP API-ийн status code-ийг Python функцийн exception-тэй адил утгаар хэрэглэхгүй. `public API` нь контекстоос шалтгаалан HTTP интерфейс эсвэл Python-ийн нийтэд хэрэглэх функцүүдийг заана.
- Үнэ, хугацаа, ачаалал, хувилбарын тоон утгыг эх сурвалж эсвэл батлах шаардлагатай шийдвэртэй нь хамт бичнэ.
- “Ажиллана”, “баталгаажсан”, “нийтэлсэн” гэдэг үгийг ажиллуулсан log, тест, URL эсвэл хяналтын нотолгоотой үед хэрэглэнэ.
